# i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add i18n infrastructure (locale resolution, a locale-switch endpoint, i18next on the frontend) across Rails views/flash, the session-authenticated JSON API, and Inertia/React pages — shipping with `en` only, structured so a second locale is data-only.

**Architecture:** A shared `SetsLocale` controller concern resolves `I18n.locale` per request from `cookies[:locale]` → `Accept-Language` header → `en`, included in both `ApplicationController` (Inertia + plain MVC) and `Api::V1::BaseController` (JSON API, which does NOT inherit from `ApplicationController`). `InertiaController` shares the resolved locale as a prop; the frontend boots `i18next` from that prop and re-syncs it on every Inertia navigation. A `PATCH /locale` endpoint sets the cookie; a `LocaleSwitcher` React component calls it then reloads the page.

**Tech Stack:** `http_accept_language` gem (new), `i18next` + `react-i18next` (new npm deps), existing `config/locales/*.yml`, existing `js-routes`, existing Inertia `inertia_share` pattern, existing Vitest setup.

**Spec:** `docs/superpowers/specs/2026-09-26-i18n-design.md`

## Global Constraints

- No `users.locale` DB column — per-user persisted preference is explicitly deferred (spec: "Out of scope").
- No URL-based locale routing (`/en/...`) — locale stays invisible in the URL.
- Only `en` ships with real content this round; structure must allow adding a locale via new yml/json files alone.
- Backend strings (flash/API errors/Devise) live in `config/locales/*.yml`; frontend UI strings live in `app/frontend/locales/*.json`. These are two separate sources of truth — do not try to generate one from the other.
- Locale resolution priority, identical everywhere: `cookies[:locale]` → `Accept-Language` header (matched against `I18n.available_locales`) → `I18n.default_locale` (`:en`).
- Only locales in `I18n.available_locales` may ever be accepted from a cookie or header value (never pass raw header/cookie input straight to `I18n.locale=`).

## Review Focus

- Malformed/spoofed `Accept-Language` header (e.g. `Accept-Language: ../../etc`, empty string, or a locale not in `I18n.available_locales` like `fr`) must not raise `I18n::InvalidLocale` and must fall through to `en`.
- A `locale` cookie holding an unsupported/garbage value (tampered by a client) must not raise and must fall through to the header/default, not crash the request.
- `PATCH /locale` with an invalid `locale` param (e.g. `"xx"`, missing, empty string) must reject with a 4xx and must NOT set the cookie.
- `Api::V1::BaseController` requests (which bypass `ApplicationController` entirely) must still get locale resolution — this is easy to silently skip since it's a separate inheritance chain.
- Cookie must win over a differing `Accept-Language` header on the same request (priority order must be exact, not "last one wins" by accident of load order).

- [ ] **Step 3: Write the concern**

Create `app/controllers/concerns/sets_locale.rb`:

```ruby
# frozen_string_literal: true

module SetsLocale
  extend ActiveSupport::Concern

  included do
    around_action :switch_locale
  end

  private

  def switch_locale(&action)
    I18n.with_locale(resolve_locale, &action)
  end

  def resolve_locale
    locale_from_cookie || locale_from_header || I18n.default_locale
  end

  def locale_from_cookie
    candidate = cookies[:locale]
    candidate&.to_sym if candidate.present? && I18n.available_locales.include?(candidate.to_sym)
  end

  def locale_from_header
    http_accept_language.compatible_language_from(I18n.available_locales)
  end
end
```

```ruby
# frozen_string_literal: true

class LocaleController < ApplicationController
  def update
    locale = params[:locale].presence
    return head :bad_request if locale.blank?
    return head :unprocessable_content unless I18n.available_locales.include?(locale.to_sym)

    cookies[:locale] = { value: locale, expires: 1.year }
    head :no_content
  end
end
```

Create `app/frontend/lib/i18n.ts`:

```ts
import i18next from 'i18next'
import { initReactI18next } from 'react-i18next'
import en from '@/locales/en.json'

const resources = {
  en: { translation: en },
}

let initialized = false

export async function initI18n(locale: string): Promise<void> {
  if (initialized) {
    return syncLocale(locale)
  }
  initialized = true
  await i18next.use(initReactI18next).init({
    resources,
    lng: locale,
    fallbackLng: 'en',
    interpolation: { escapeValue: false },
  })
}

export function syncLocale(locale: string): void {
  if (i18next.language !== locale) {
    i18next.changeLanguage(locale)
  }
}

export default i18next
```

- [ ] **Step 4: Write the component**

Create `app/frontend/components/LocaleSwitcher.tsx`:

```tsx
import { router } from '@inertiajs/react'
import { useTranslation } from 'react-i18next'
import { localePath } from '@/lib/routes'

export default function LocaleSwitcher() {
  const { t, i18n } = useTranslation()

  const availableLocales = ['en']

  const handleChange = (event: React.ChangeEvent<HTMLSelectElement>) => {
    const locale = event.target.value
    router.patch(
      localePath(),
      { locale },
      {
        onSuccess: () => router.reload(),
        preserveState: false,
      }
    )
  }

  return (
    <label className="flex items-center gap-2 text-sm">
      <span className="sr-only">{t('locale.switcher.label')}</span>
      <select
        value={i18n.language}
        onChange={handleChange}
        className="rounded border bg-background px-2 py-1 text-sm"
      >
        {availableLocales.map((locale) => (
          <option key={locale} value={locale}>
            {locale.toUpperCase()}
          </option>
        ))}
      </select>
    </label>
  )
}
```
