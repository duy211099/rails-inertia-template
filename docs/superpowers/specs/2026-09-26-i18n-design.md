# i18n Design

Date: 2026-09-26

## Goal

App got zero i18n now: no locale detect, no locale switch, no frontend translation lib, only `en.yml` / `devise.en.yml` exist, used ad hoc for two flash msgs. Add full i18n infra across backend (Rails views/flash/mailers), API (session-auth items API, Swagger docs), frontend (Inertia + React pages). Ship `en` only, structure so second locale later = data-only (new yml + json files, zero code change).

## Locale resolution

No URL prefix (`/en/...`) — locale invisible in URL, carried via cookie/session only. No per-user stored pref for now — every visitor, signed in or not, resolve locale same way.

Priority chain, applied same to Inertia page requests, plain-MVC (admin) requests, API requests:

1. `locale` cookie (set when user explicit pick locale via locale-switcher endpoint)
2. `Accept-Language` request header (best match against `I18n.available_locales`)
3. `I18n.default_locale` (`:en`)

Per-user stored pref (`users.locale`) deliberate deferred — add later as small follow-up (new column + one more step top of priority chain), no touch rest of design.

Resolution happen once per request in `ApplicationController`, apply uniform to `InertiaController`, `AdminController`, API controllers, no each need own logic.

## Backend

### Schema

No schema change. Locale resolve purely from cookie/header per request; nothing persist to `users`.

### Locale resolution concern

`app/controllers/concerns/sets_locale.rb`, included in `ApplicationController`:

- `around_action :switch_locale`
- `switch_locale` resolve via priority chain above, wrap action in `I18n.with_locale(resolved_locale) { yield }`
- Resolution helper check, in order: `cookies[:locale]`, `http_accept_language.compatible_language_from(I18n.available_locales)` (via `http_accept_language` gem — new dependency), `I18n.default_locale`
- Only locales in `I18n.available_locales` ever accept from cookie or header value, avoid `I18n::InvalidLocale`

### Explicit locale switching

New endpoint, `PATCH /locale` (`config/routes/locale.rb`, drawn from `routes.rb` alongside other route files):

- Params: `{ locale: "en" }`
- Validate against `I18n.available_locales`
- Set `cookies[:locale]` (long-lived, e.g. 1 year)
- Respond `head :no_content` for API/fetch use; frontend locale switcher call this then reload current Inertia page (via `router.reload()`) so shared props re-render in new locale

### Translations

`config/locales/*.yml` stay source of truth for backend-rendered strings: flash msgs, Devise strings (`devise.en.yml`, existing), API error msgs, mailer content. Files below top level mirror `app/controllers` structure — e.g. `config/locales/items/en.yml` for `ItemsController`'s keys, `config/locales/api/v1/en.yml` for `Api::V1::BaseController`'s — rather than one growing flat file. Rails load `config/locales/**/*.yml` recursively by default (`Rails::Engine::Configuration`), needs no extra config. Second locale later = one new file per existing file (e.g. `config/locales/items/vi.yml`, `config/locales/devise.vi.yml`), not restructure.

### API error messages

API controllers (`app/controllers/api/`) already return JSON error bodies — these run through `I18n.t` for message text so `Accept-Language` on API clients (Swagger UI, curl, etc.) work without any session/cookie. No change to error response shape, just how message string produce.

## Inertia bridge

`InertiaController` gain one more `inertia_share`, alongside existing `flash` and `user` shares:

```ruby
inertia_share locale: -> { I18n.locale.to_s }
```

Frontend read this on every page load/visit, keep i18next active language sync with server-resolved locale — first paint never flash wrong language, locale stay consistent across Inertia partial reloads.

## Frontend

### Library

`i18next` + `react-i18next` (new npm deps).

### Structure

- `app/frontend/locales/<namespace>/en.json` — one i18next namespace per folder, same mirroring convention as backend's `config/locales/<controller-path>/en.yml`, but independent from it (separate source of truth by design — backend and frontend strings don't overlap in practice: one server strings, other UI copy). `common/en.json` hold UI strings shared across pages (e.g. locale switcher); page-specific namespace add same way once that page got copy to translate.
- `app/frontend/lib/i18n.ts` — i18next init: register namespace bundle(s) (`defaultNS: 'common'`), set initial language from Inertia `locale` shared prop (read at bootstrap in `app/frontend/entrypoints/inertia.tsx` before first page render)
- Inertia's `router.on('navigate', ...)` (or equiv lifecycle hook) sync `i18next.changeLanguage()` if shared `locale` prop change between visits (e.g. after user hit switch-locale endpoint, page reload)

### Usage in components

Standard `react-i18next` `useTranslation()` / `t()` calls in page and UI components. No new abstraction layer beyond what lib provide — YAGNI given single-locale launch.

## Locale switcher UI

Small dropdown/select component (visible in shared layout, e.g. next to existing user menu) listing available locales — shared to frontend as `availableLocales` Inertia prop (`I18n.available_locales` server-side; currently just `["en"]`) rather than hardcode in component, so two can't drift — call `PATCH /locale` on change, then reload. Scaffold even with one locale so plumbing (endpoint, cookie, frontend call) exercise and test now rather than add later untested.

## Testing

- Request spec for `PATCH /locale`: set cookie, reject invalid locale
- Request spec assert `Accept-Language` header change `I18n.locale` when no cookie present
- Request spec assert cookie win over differing `Accept-Language` header
- Frontend: vitest unit test for `lib/i18n.ts` init reading `locale` prop
- No translation content correctness tests (single locale, `en` keys mirror existing English strings)

## Out of scope

- Per-user stored locale pref (deferred, see Locale resolution)
- Any second locale's actual translated content (structure only)
- URL-based locale routing
- RTL layout support
- Locale-aware number/date formatting beyond what `I18n.l` / `Intl` already give out of box
- Translating existing seed/fixture data
